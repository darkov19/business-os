# Business OS Artifact Map v1

Status: Draft for discussion
Purpose: Define the document outputs, decision records, and working artifacts that the Business OS should generate across different user intents, business contexts, and module workflows.

---

## 1. Why The Artifact Map Matters

The Business OS should not end in conversation alone.

It should convert thinking, research, and decisions into durable artifacts that the user can review, refine, share, and reuse.

The artifact map answers:

- what documents should be created
- when they should be created
- what module or workflow should produce them
- which artifacts are foundational versus optional
- how artifacts connect into a coherent business dossier

---

## 2. Design Principles

### 2.1 Documents Should Match Decision Readiness

The OS should not generate polished strategy documents when the user has only vague inputs.

Early-stage users need lighter artifacts first.

### 2.2 Artifacts Should Be Modular

Each artifact should stand on its own while also fitting into the larger system.

### 2.3 Artifacts Should Preserve Uncertainty

Documents should clearly separate:

- known facts
- assumptions
- researched evidence
- decisions made
- unresolved questions

### 2.4 Artifacts Should Support AI Reuse

Outputs should be structured so later agents or skills can build on them without needing to rediscover the same context.

### 2.5 Artifacts Should Reflect Real Business Work

The OS should favor practical working docs over generic pitch-style business plans.

---

## 3. Artifact Layers

The artifact system should have four layers.

1. Foundation Artifacts
2. Decision Artifacts
3. Operating Artifacts
4. Control Artifacts

### 3.1 Foundation Artifacts

These establish basic clarity around the business.

### 3.2 Decision Artifacts

These document important strategic choices.

### 3.3 Operating Artifacts

These guide execution and day-to-day business activity.

### 3.4 Control Artifacts

These track assumptions, risks, evidence, and unresolved questions.

## 11. Artifact Maturity Levels

The OS should not create the same depth of document at every stage.

### Level 1: Exploratory Notes

Use when:

- user is early-stage
- evidence is weak
- many assumptions remain

Examples:

- founder brief
- opportunity memo
- validation memo

### Level 2: Structured Strategy Docs

Use when:

- core business choices are becoming clearer

Examples:

- positioning memo
- offer architecture
- route-to-market memo
- pricing memo

### Level 3: Execution Docs

Use when:

- launch or operational readiness is being built

Examples:

- operations playbook
- launch readiness doc
- marketing plan

### Level 4: Control And Governance Docs

Use when:

- the business needs ongoing discipline across changes

Examples:

- decision gate tracker
- KPI framework
- expansion decision dossier
