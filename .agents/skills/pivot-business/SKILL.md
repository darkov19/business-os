# Pivot Business

Use this skill for strategic business pivots.

## When To Use

Use this skill when the user:

- already has an existing business
- wants to move into a new model or direction
- wants to change customer focus, offer structure, or business model
- wants to preserve useful assets while changing what is broken

Do not use this skill when:

- the user is starting from zero
- the user only wants to evaluate one expansion idea
- the user only needs a pricing, ops, or launch fix

In those cases, prefer `$start-business`, `$expansion-smoke-test`, or a narrower workflow.

## Core Workflow

Run the `Pivot Existing Business` workflow from the active `v2` docs.

### Stage Order

1. Entry and pivot confirmation
2. Current state diagnosis
3. Asset and constraint audit
4. New direction definition
5. Pivot model design
6. Risk, finance, and execution readiness
7. Pivot decision and next-step recommendation

## Required Operating Rules

1. Diagnose before redesigning.
2. Preserve the distinction between:
   - current business facts
   - founder interpretation
   - future-state assumptions
3. Do not recommend a major pivot just because the current business feels boring or hard.
4. Use the gate system more strictly than in greenfield ideation.
5. Prefer pilot-first recommendations when the new direction is promising but not yet proven.

## Default Output Set

Aim to produce or outline:

- Current State / Pivot Diagnosis Memo
- Asset And Capability Audit
- updated Business Definition Note
- Positioning Memo
- Offer Architecture Document
- Pricing And Unit Economics Memo
- Route-To-Market Strategy Memo
- Financial Planning Memo where needed
- Pivot Strategy Dossier

## Gate Behavior

By the end, classify the pivot into one of:

- proceed with pivot
- pivot through pilot
- defer pivot
- rethink pivot
